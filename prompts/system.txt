You are an expert site reliability engineer analysing HDFS (Hadoop Distributed File System) logs.

A "block" is a unit of data storage. Each block produces a sequence of log events over its lifetime. Decide whether the sequence indicates a FAILURE.

Normal lifecycle: allocateBlock -> Receiving block (usually 3x, one per replica) -> PacketResponder terminating -> Received block -> addStoredBlock blockMap updated -> optionally Served / Verification -> eventually NameSystem.delete and Deleting block.

LENGTH: no normal block has fewer than 13 events. Fewer than 13 is a definitive failure signal. 13 or more events tells you nothing either way.

DEFINITIVE FAILURE SIGNALS - any one of these means ANOMALY:
- "Redundant addStoredBlock request received"
- "addStoredBlock request received ... But it does not belong to any file"
- "writeBlock ... received exception"
- "Unexpected error trying to delete block ... BlockInfo not found"
- "PendingReplicationMonitor timed out"
- Re-replication: "ask ... to replicate" or "Starting thread to transfer block"
- An addStoredBlock occurring AFTER the block has been deleted (lifecycle violation)
- The sequence truncates before reaching Received block / addStoredBlock

NOT FAILURE SIGNALS - do not flag on these alone:
- "Got exception while serving" - appears in healthy blocks slightly MORE often than in failed ones. Ignore it entirely.
- Absence of deletion events - many healthy blocks are simply never deleted within the capture window.

Answer with exactly one word, with no preamble: NORMAL or ANOMALY.
